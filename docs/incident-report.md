# Incident 01 — SSH Brute-Force Detection

## Executive Summary

On July 27, 2026, host `10.77.0.10` generated 12 unsuccessful SSH login
attempts against the `soc-test` account on server `10.77.0.20`. Wazuh
correlated the authentication failures and classified the activity as an SSH
brute-force attempt. No successful login was identified.

This was a planned and authorized simulation performed inside an isolated
local lab.

## Key Details

| Field | Value |
| --- | --- |
| Source | `SOC-Kali`, `10.77.0.10` |
| Destination | `SOC-Target`, `10.77.0.20` |
| Account | `soc-test` |
| Service | SSH |
| Attempts | 12 |
| Successful login | No |

## Event Count Explanation

The target recorded 12 `Failed password` entries. In Wazuh, 11 events remained
classified under rule `5760`, while one event was elevated to the correlated
rule `5763`.

```text
11 × rule 5760 + 1 × rule 5763 = 12 attempts
```

## Assessment

The alert was a true positive generated by an authorized simulation. The
investigation found no successful authentication. The Wazuh agent, SSH/PAM
decoders, and correlation rules operated as expected.

The next stage is to configure SSH key-based authentication, disable password
authentication, and repeat the controlled test to compare the detection
results after hardening.
